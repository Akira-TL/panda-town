# 成熟玩法研究与 Panda Town 采用方向

日期：2026-10-31。问题边界：哪些已有机制适合一局 5–8 分钟的三维小镇，并能支持 PandaAI 的行为理解？本次阅读官方资料，没有实际试玩这些游戏。用户后续已将结尾收敛为画像面板，原先提出的推荐与后续练习不再采用。

## 案例事实与采用判断

| 案例 | 官方可核验事实 | 本项目采用的设计判断 |
| --- | --- | --- |
| 大富翁11 | 发行商说明包含掷骰移动、购买土地、建造升级、租金、银行和电脑对手。 | 保留移动、机会选择与资产反馈，按既定需求取消破产淘汰和攻击道具。 |
| Ubisoft 的 Monopoly | 官方介绍城市随经营进度变化，也提供特殊目标缩短游戏。 | 使用唯一开店目标与固定回合；把进展做成招牌、营业状态和场景变化。 |
| 集合啦！动物森友会 | Nintendo 的官方介绍强调可个性化的岛屿环境。 | 借鉴对生活场所的亲近感；使用少量有功能的地标，不引入自由建造和长周期收集。 |
| 奇异人生 | 官方移植版手册说明环境互动、对话选项、后续事件与人物关系会受选择影响，并可回看关键选择。 | 使用短对话、明确选择、即时后果和后续呼应，结尾回看自己的证据；不引入时间倒流。 |

## 对三维场景的直接要求

场景承担四项功能：识别地点、理解路线、看见经营后果、建立角色记忆。沿街招牌帮助辨认功能；岔路预览帮助作选择；摊位开张和咖啡馆结局呈现进度；重复见到的居民使前后事件发生联系。

第三人称用于在场景中行走和接近角色，全局视角用于理解分支与对手位置。同一个行动不因镜头改变而改变结算。暖色光照与柔和材质沿用用户选定的概念图，不能用概念图代替未来真实三维场景。

## PandaAI 的适合位置

官方数据文档说明 PandaData 支持历史与实时市场数据，通过 SDK、MCP 或 REST 接入，实际访问依赖账号与数据权限。因此，当前先明确使用人工编制的演示行情；未来获得授权后，再替换为有来源与时间边界的历史片段。

来源：[PandaAI 数据服务文档](https://www.pandaaiquant.com/docs/data)。

设计上把 PandaAI 放在小镇研究站、事件中的信息查看和结尾画像面板的证据解释中。QuantSkills 首页本轮未返回可读条目，不能据此声称已经选择或接入某个具体技能；当前产品也不提供技能推荐入口。

## 研究结论

采用成熟的回合与资产循环、场景状态反馈和剧情后果机制，集中原创工作在童话小镇的三维体验，以及游戏行为与 PandaAI 所需画像信息之间的联系。具体应用方案见 [玩法与场景方案](../gameplay-direction.md)。

仍需未来验证：实际阅读与行走时长、三维场景性能、事件重复感、经济平衡和画像解释的可理解性。当前研究不证明这些指标已经达标。
