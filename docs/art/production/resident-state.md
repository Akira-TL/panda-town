# 居民与账本状态的场景表现

居民从已记录的 Tripo 熊猫模型和项目自建骨骼派生，不声称独立店主图生成成功。帽子、围裙及道具几何为项目自建；道具复用已生成布料、木材纹理。桌面居民使用一次加载的手机档骨骼基体共享几何和材质，手机直接复用玩家已加载的同档模型，各居民拥有独立骨骼与待机播放器。

七位居民分别位于面包店、杂货店、集市、研究站、银行、礼品店和对手店。名称为 `Resident:<地点标识>`，玩家到店时居民转向玩家回应；角色动画服从减少动画设置，不依赖整个模型跳动。

场景仅消费页面从账本传入的四项可选属性，不计算收入或推进回合，不因数组引用变化重建场景：

| 属性 | 实际可见表现 |
| --- | --- |
| purchasedItems | 仅为本局已有的 bread、bread-gift、practical-gift、novel-gift 显示纸袋或礼盒；repair-service 不生成可携带物件 |
| toolPending | 仅显示待交货木箱，不显示已生效工具 |
| toolQuality | 交货后显示二手扳手或优质工具组；没有工具时隐藏 |
| opponentStallOwned | 显示对手的真实集市模型派生摊位；模型与原摊位共享资源 |

道具根名称为 `PurchasedItems`、`PlayerWorkshop`、`OpponentStall`。轻量验证属性 `data-scene-items`、`data-tool-state`、`data-opponent-stall` 从实际对象的可见性生成；`data-resident-count` 在居民真实创建后记录数量。

机械检查覆盖空状态、已购面包与礼物、服务不生成物件、待交货不提前展示工具、交货后优质工具、对手摊位和清空状态，类型检查通过。真实运行仍应依次检查购买／待交／交货以及重开、清除后的截图，不能只以数据属性或编译通过宣称视觉验收完成。
