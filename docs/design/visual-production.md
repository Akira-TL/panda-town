# 视觉生产与对照验收

状态：首版规格的配套生产要求。用户已授权开始资产制作及游戏实现。所有涉及场景、角色、物品、对话、画像面板的任务必须读取并执行。

## 已授权的模型生产路径

当前分工以用户 2026-10-31 最新决定为准：Agent 使用 imagegen 生成适合图像转三维的单独物件图，打包 ZIP 到用户下载目录；用户在 Tripo 生成模型，将 GLB 保存在下载目录后交给 Agent。输入图清单和导出说明见[模型生成交接](../art/model-generation-handoff.md)。模型生成环节由用户操作，Agent 负责输入图、接收校验、Blender 加工、集成及画面对照。

记录生成设置与来源，优先使用携带材质的 GLB。需要降低面数、修正比例/朝向/原点、材质或动作时，使用已安装 Steam Blender；用户已进一步授权通过 CLI 或 MCP 加工，已验证的批处理脚本位于 `scripts/assets/`。保留原始模型与衍生版本，不覆盖用户原有工程。现有浏览器登录态可用于按需核对来源和许可；不自动购买订阅或额外付费。未完成许可核验的模型不得宣传可按 MIT 重新授权。

上传图要求单一完整物体、干净背景、中性照明、无遮挡；角色使用便于重建的姿势，建筑展示完整轮廓，不将整镇图用于生成一个不可拆分的地图模型。图像是建模输入或纹理素材，下载的模型须实际在双镜头中检查几何与材质。

## 1. 效果图先行

先读取可用的 imagegen Skill，并用 imagegen 生成目标效果图。已有选定风格锚点为 [童话小镇参考图](../art/fairytale-town-reference.png)，应先查看原图再作参考编辑。保留木构灰泥、柔和日光、圆润熊猫、曲线道路、溪流桥梁与错落布局，不重新征集风格方向。

第一批效果图必须覆盖：完整小镇全局布局、第三人称街景、一个店前对话画面、咖啡馆开张、桌面画像面板与手机版面板。全局图与街景使用相同地标、屋顶色和空间关系。效果图里的示意文字不直接作为正式界面文字。

先确认效果图内部一致且满足已定方向，再进入素材生成。沿用已批准风格的局部制作由 Agent 自查即可；若要改变画风或主要布局，提交对比图说明差异再让用户决策。imagegen 不可用时保留任务未完成并说明缺少能力，不能跳过出图阶段或用其他图片伪称生成结果。

完成依据：项目内保存原图、提示词、参考图关系、生成日期、预期镜头及用途，用户能直接查看。生成目录的临时路径不应成为游戏运行依赖。

## 2. 参考效果图生成元素图

以已完成的效果图作为 imagegen 参考，按实际用途逐项生成素材。一个可用文件对应一个用途；元素拼版可用于讨论，但不能把带邻近物件、边框或说明文字的拼版直接当纹理。透明背景的资产需明确请求真实透明通道，不能带棋盘格背景。

| 素材组 | 首版最低内容 | 用途与限制 |
| --- | --- | --- |
| 熊猫与居民 | 玩家、对手、店主、研究站工作人员头像；玩家正侧背参考 | 头像用于对话；正侧背作为建模依据，不是三维模型 |
| 建筑表面 | 木、灰泥、屋瓦、布篷四类可重复纹理 | 避免把固定阴影烘进所有表面；检查接缝与重复感 |
| 店铺识别 | 面包、杂货、集市、研究站、银行、礼品、对手店、咖啡馆八组标识元素 | 图形由 imagegen 生成；正式店名和 PandaAI 名称用可读文字叠加，避免生成字错误 |
| 决策物件 | 二手工具、优质工具、礼物、纪念物、现金、摊位、投资凭证 | 图标/贴图与实际经济含义一致，不能靠颜色唯一编码 |
| 场景细节 | 告示、花草、窗饰、旗帜和桌面小物元素 | 靠近玩家的物体按需建模，远景才可用平面装饰 |
| 画像界面 | 熊猫称号插画、区块装饰与证据图标 | 数值、图表、正文、按钮使用真实界面组件，支持缩放和辅助技术 |

每个素材记录稳定标识、所属效果图、提示词、原始文件、游戏用衍生文件、尺寸、透明通道、生成来源、负责人和实际使用位置。未使用或失效素材单独注明，不能以生成数量充当完成标准。禁止未经许可引用第三方人物、商标素材或宣传已获 PandaAI 品牌授权。

完成依据：游戏可直接读取的元素文件已在项目内，检查透明边缘、裁切、清晰度、纹理接缝，并能从清单追到效果图及实际使用处。

## 3. 制作真实三维场景

先以简单体块验证道路、地标尺度、遮挡与双镜头，再制作与效果图对应的形体和细节。建筑采用不等高屋顶、进退错落门面和不同朝向，避免一排等距盒子；道路是连续弯曲的地面形体，不以相同方块拼出棋盘。

模型优先共享基础几何与材质，但八处主要建筑必须能由轮廓、入口与招牌区分。熊猫至少具备待机、行走、交谈响应；首版可使用程序化或自行制作的模型，不假设 imagegen 自动输出可用的三维网格。必须记录制作方式和许可。

将生成纹理、招牌图形、头像和物件图标接入实际材质与界面。光照以暖色主光和柔和环境光统一全镇，阴影接地，材质粗糙度及明暗避免塑料玩具般一片高光。溪流、植被、烟雾等动效服从性能预算及减少动画设置。

跨街区共享尺度、色彩、光照、熊猫比例由最小场景任务固定；各街区任务交付自己的地标与事件场景，不独立更换全局色调、相机或资产加载方式。先保证双视角下完整形体，再按可见面积安排细节。

完成依据：第三人称和俯瞰看到同一建筑、角色和资产状态；可旋转观察，有正确遮挡和光照；画像与对话中的生成图片已经实际使用。

## 4. 对照效果图验收

固定相近镜头、光照和场景状态，保存真实浏览器截图，与效果图并排比较。逐项记录：空间布局、弯道丰富度、建筑错落、熊猫比例、材质与配色、光照阴影、画面层次、对话可读性和手机裁切。

差异分为必须修复和已解释取舍：布局僵硬、缺主要地标、平面图代替三维、角色比例明显偏离、弹窗遮住操作、招牌不可读必须修复；为手机性能减少远景装饰可以记录取舍，但不能降低核心玩法可读性。不要发明“像素相似度合格”来替代视觉检查。

提交证据必须包含效果图、实际截图、对应资产记录、尚未解决差异。只有概念图或孤立模型预览不能作为最终场景验收。效果图明确标为概念图，运行截图明确标为运行截图，不能相互冒充。

## 5. 每个视觉任务的交付清单

- imagegen 目标效果图及提示词、参考关系。
- 依据效果图生成并实际使用的元素图及来源清单。
- 涉及的真实三维模型、材质、光照或可操作界面。
- 任务专属互动从触发到后果、记录的完整演示。
- 对应镜头的实际截图、差异说明及修复结果。
- 资产大小与加载结果；不把未完成的视觉工作转给末尾统一美化任务。
