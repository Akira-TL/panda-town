# 事件内容与只读画像接口

关联任务为 T13、T14、T15，来源为首版规格。当前只完成纯内容与分析模块，不代表界面、图像或全流程任务验收通过。

## 接入

`content.ts` 导出十六个地点、路线连接、十二个基础事件、两道固定客观题与资料。`getEventForLocation(state, locationId)` 根据实际资产、日数和既有记录选择事件；外壳仅在落点调用一次，再通过核心 `open-event` 冻结选项。正文通过 `getEventCopy(event.id)` 取得。不能在切镜头或展开资料时重新选事件。

资料题通过核心 `inspect`、`compare`、`answer` 记录；资料比较必须先展开两个不同来源。营业样例是开局前已公布的历史演示记录，不是未来三天的行情。投资资料只显示当前报价，未来结果由核心掌握。

## 画像输出

`buildProfile(readonly Evidence[])` 只读本局证据，返回称号、消费、交易、信息、兴趣、一般人格、知识及证据卡。界面直接展示各项 `text/status/count/opportunities`，用 `evidenceIds` 展开对应卡片。已提供所有中文正文，不要求语言模型补写结论。

每条卡保留场景、日数、地点、现金、选项可用性与已看资料。知识表现从固定题目目录复核答案，不由投资收益或行为速度换算。投资比例以选择时现金为分母；所有百分比只表示真实投入比例，不表示心理置信度。

除真实工作次数外，跨事件概括按 `contextId` 去重；同一资料反复展开、同事件不同地点变体不会增加独立情境。消费比较要求两个主题商品都可购买。随机路过没有动作记录，不计兴趣；未展示、余额不足也不计拒绝。

一般人格无数值评分。开放性相关线索仅陈述两个独立消费情境的新奇选择；交谈、核对、合作均限定在实际行为，情绪稳定性未评估。相反方向的消费或独处行为保留证据，不能强行概括一致方向。

四次工作称号按真实提交动作计数，即使同属盘点事件仍为四次工作；两个独立情境的资料比较优先触发看账称号。默认称号不附心理意义。
