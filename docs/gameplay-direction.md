# Panda Town 玩法与三维场景方案

状态：规划方案；未开发、未试玩。用户于 2026-10-31 授权 Agent 基于成熟案例自行收敛常规玩法细节，减少逐项询问。此前已经确认的约束继续有效。

依据见 [成熟玩法研究](research/gameplay-cases.md)。本文件是连贯的设计提案，尚未解决的画像测量问题仍留在对应决策问题中。

## 1. 玩家要经历什么

熊猫带着启动资金来到童话小镇，希望在八天后开一家咖啡馆。每回合代表一天：掷骰子，沿街自动行走，在岔路选方向，在商店或居民面前完成一次主要决策。经营、消费和投资共同影响现金与资产。第八天统一结算，达标开张，未达标则继续筹备。

只有一个目标和两种结果。开店成败与画像分开，电脑对手不会导致玩家提前出局。

## 2. 每回合循环

1. 显示当天信息、现金、资产与开店资金差额。
2. 玩家掷普通六面骰，按点数移动相应数量的沿街停靠点。
3. 岔路处暂停并预览两条路可经过的地点，选择后继续使用剩余步数。
4. 到达地点后镜头靠近角色，出现简短对话与通常三个选项；必要时可展开查看证据。
5. 确认后展示现金变化、资产变化或后续机会，并让场景作出对应变化。
6. 电脑对手完成一个简短行动；结算当日收入，进入下一回合。

移动中的中间地点只作经过表现，不逐店弹窗；每回合保留一个主要事件。掷骰结果公开，不为强迫玩家看到某个事件暗改点数。

引导信息、第四天的市场公告和第八天的结算通过角色来信或公告传达，不要求掷出特定点数才能继续。它们不额外消耗行动，避免随机落点阻断故事。

规划时长：引导约 20–30 秒，每回合约 25–40 秒，结尾约 40–60 秒；这些只是预算，决策不限时，不能保证每位玩家都在八分钟内结束。

## 3. 路线与三维布局

采用围绕溪流弯曲的主路，加两条分出再汇合的短支路；道路有高低与宽窄变化，以拱桥、广场和坡道连接。内部设 16 个停靠点：12 个主路地点、4 个支路地点。停靠点绑定店门、摊位、长椅或居民，不绘制地板格子。

每条边代表移动一步，长短不同的视觉路段通过步数预览解释。进入支路后继续向前并汇合，不在同一回合折返刷收益。全局视角只在玩家准备移动或选路时显示道路高亮和可达地点，平时保持生活化场景。

### 八处主要建筑

| 地点 | 空间特征 | 承载内容 |
| --- | --- | --- |
| 面包店 | 弧形瓦顶、暖光橱窗、面包货架 | 工作机会、即时消费、熟人后续 |
| 杂货铺 | 花草门廊、外摆货箱 | 价格与品质取舍、开店物品 |
| 集市摊位 | 布篷与可更换招牌 | 小额经营与收入到账 |
| PandaAI 研究站 | 木屋与玻璃温室结合，入口有简洁品牌标识 | 局内查看证据、比较行情，形成可解释的行为记录 |
| 银行 | 圆拱入口、清楚的服务标识 | 资产估值与结算说明，不做复杂信贷 |
| 礼品店 | 橱窗、彩色遮阳棚 | 新奇消费、赠礼及角色回应 |
| 对手的小店 | 与玩家不同的外墙色和招牌 | 看见对手进展、交易与合作 |
| 待开张咖啡馆 | 河畔露台、最初关闭的门窗 | 全局目标地标与最终开张演出 |

其他八个停靠点利用广场、公告牌、小桥、露天修理摊、花园、街头音乐角、河岸观景点和码头形成户外事件。装饰房屋只填充远景，不扩大可进入室内数量。

默认不加载独立室内场景：交谈和决策在门口、露台或摊位旁完成。角色包括玩家、一个对手和少量反复出现的居民；通过服饰与职业道具区分，避免大量独立角色制作。

### 两种镜头

- 第三人称：略抬高的后方跟随，兼顾路面与招牌；靠近交谈对象时转为侧前方构图。
- 全局：俯瞰同一座小镇，可旋转和缩放，查看位置、岔路与已拥有资产；不改变游戏状态。
- 对话弹窗保留背景地点和角色。电脑使用下方对话区，手机使用下半屏面板，避免把场景完全盖住。

## 4. 事件怎样带来选择

首版设计约 12 个可复用事件及少量条件变体，一局遇到其中 8 个；相同地点再次到达时使用后续对话，不重复发放一次性奖励。

| 事件类别 | 代表情境 | 可观察行为与实际后果 |
| --- | --- | --- |
| 工作 | 接确定报酬的临时工作，或花时间了解经营机会 | 选择确定收益或未来机会；都需有明确代价 |
| 消费 | 购买便宜二手工具、较贵且可靠的工具，或暂不购买 | 价格、品质和现金保留；后续经营体现物品差异 |
| 经营 | 租摊位获得后续收入，或保留现金 | 即期现金与持续收入的取舍 |
| 信息 | 直接接受热销传闻、查看销量记录，或找另一条证据 | 信息查看与证据比较；不能把“不查看”直接当作能力低 |
| 投资 | 观察两组演示行情，决定不参与、小额参与或较大额参与 | 同一可见信息下的投入与风险选择 |
| 调整 | 行情变化后继续持有、退出或先核对消息 | 行为理由、可用现金与后续机会共同影响解释 |
| 合作 | 对手提出共同采购或转让机会 | 条款比较与合作选择，避免固定的道德正确答案 |
| 收尾 | 保留经营资产或按已知条件变现 | 为开店筹现金，允许玩家理解资产与现金的区别 |

对话正文尽量一至两句，通常三个可直接点击的选项。确定成本明确显示；未知结果说明不确定性，不提前泄漏后来的行情。选择提交前可查看详情，提交后不在同一局无限回退以挑选最好结果；局末可重开体验另一条路径。

消费获得的纪念物与生活体验可被结尾回顾，但不再引入幸福值等独立资源。暂未选择的选项不能按“玩家拒绝”记录，余额不足的灰色选项也不能算偏好证据。

## 5. 经济设计草案

以下数值由 Agent 拟定，仅用于纸面讨论，不是已验证的平衡结果。

- 初始现金 1000，开店要求最终可用现金至少 3000。
- 每回合末固定基础工作收入 150，共八次；事件中的额外工作收入暂按 250。
- 示范经营资产：摊位投入 600，从购买后的下一回合起每回合获得 100；期末可按事先标明的 480 退出。
- 投资提供少量明确额度，不允许借款、杠杆或负现金；收益与亏损使用已标注的演示情境，不临时按玩家选择操纵结果。
- 第八回合先结算到期收益，再展示各项可出售资产的报价；玩家确认变现后按现金判断开店，不把未出售资产自动当作现金。
- 对手可竞争额外优惠与合作机会，不能封锁基础工作收入、结算服务或玩家咖啡馆。

纸面可行性例子：不投资但完成四次额外工作，现金为 1000＋8×150＋4×250＝3200。第二回合购买摊位，后续收六次收入、期末出售，再做两次额外工作，现金为 1000＋8×150－600＋6×100＋480＋2×250＝3180。这只证明相应事件序列下有不靠高风险投资达标的路径，随机路线是否提供足够机会仍须后续检查。

金额不够的消费禁用并说明缺口；投资亏损最多损失已投入金额；未达标保留完整报告，不赠送隐藏资金把失败改成成功。

## 6. PandaAI 与用户画像面板

### 游戏过程中：信息能改变选择

研究站或居民提供的“看看资料”入口显示一张简短的价格或销量图，以及来源与截至时间。初期使用人工编制的演示数据，界面标明“演示数据”。事件中的未来结果在决策提交后才揭晓。

查看、比较和选择分别记录，并保留当时余额、已有资产、可选项及可见信息。不能只记录最后买了什么，否则无法区分策略约束与个人倾向。

### 结尾：展示 PandaAI 关心的用户信息

先展示咖啡馆结果，随后直接进入用户画像面板。顶部为趣味称号、简短描述和本局结果；下方展示消费与交易偏好、信息使用习惯、一般人格线索及行为证据。具体布局见 [画像面板内容方案](profile-panel.md)。趣味称号作为游戏表达，不伪装成权威心理类型。

本设计不预先承诺从八次决策完整测出所有一般人格维度。维度映射、最低证据要求与中文题项适用性仍由画像研究和画像设计问题收敛。

### 数据与体验边界

用户已明确取消推荐任务、两分钟研究练习和外部跳转，画像面板是本局体验的终点。仅保留查看证据、重开一局和清除本局记录等操作。

默认不要求登录，行为与画像仅保存在当前设备。展示 PandaAI 关心的画像信息不等于把数据发送给 PandaAI。试玩反馈如需收集，应另行让玩家主动选择提交，不混入开始游戏或查看结果操作。

当前不声称已接入任何 PandaAI 账号、真实数据或技能。将来取得数据权限后，可在单独核验来源和授权的前提下替换局内演示行情；不会自动扩大为用户数据上传。

## 7. 当前取舍

优先把模型细节集中到八处主要建筑、熊猫动作、溪流小桥、错落道路和场景状态变化。舍弃自由建造、复杂室内、多人联机、攻击道具、债务和大量资产种类。

后续常规玩法细节由 Agent 继续按此方向收敛。只有涉及改变已确认产品目标、外部账号授权或真实数据用途等问题才再次询问用户。当前仍不开发，画像效度与完整内容定稿也尚未完成。
