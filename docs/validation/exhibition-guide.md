# 展会本地操作与交接

当前版本有实际熊猫模型和可完成的八回合玩法。八处建筑的正式模型、最终画面与实体手机性能尚未验收，现场应保留“开发预览”的真实状态说明。

## 开场准备

从项目根目录使用 Git Bash，先安装锁定依赖，再构建和启动本地生产服务：

```sh
npm ci --cache .cache/npm
PANDA_MODE=production npm run build
PANDA_MODE=production bash scripts/start.sh
```

打开 http://127.0.0.1:3018。生产服务仅监听本机，浏览器不需要登录。默认3000端口曾被其他服务占用，勿终止不属于本项目的进程。资源来自项目本地，不向PandaAI上传玩家记录，不使用真实资金或真实行情。

确认页面能进入游戏，而不只是HTTP200。实际模型检查应看到绿色背包、黄色围巾的熊猫；只看到圆球预览形体不等于正式模型加载完成。页面若持续停在开门文字，先检查对应模式日志，不反复修改规则或清理浏览器账号。

## 一条稳健演示路线

1. 开场点击出发，阅读唯一3000金币目标、八天期限和每晚150基础收入。
2. 每天正常掷骰，分支任选；每个地点均可选择临时工作250。该选择占用本回合主要行动。
3. 连续八天都工作，结算前应有4200。没有经营或投资资产时，确认结算后咖啡馆开张，余额1200。
4. 打开画像，展示“踏实筹备的店长”的触发依据，查看实际选择证据和未观察部分。不把财富或游戏称号解释成心理诊断。
5. 演示资料与题目均可跳过，不需要额外注册、课程或外部推荐。想展示资料比较时应按真实落点操作，不能暗改现场骰子。

自动化验证另有固定骰子序列的3200、3180及2200路径，详见 local-validation.md；它们属于测试输入，不作为正式游戏的隐藏操控。

## 换人和记录

结尾使用“清除记录”再选择“确认清除”，回到开场后再交给下一位。刷新会恢复本标签页当前局，不能把刷新当清除。重开应生成新的本局标识和空证据，不继承上一位称号或记录；连续五位完整体验后的确认清除路径已通过浏览器测试。

中途离场时，打开“资产与旅程手记”，在顶部选择“清除记录”及“确认清除”。确认前可以取消，取消保持当前局；“重开一局”及“确认重开”则创建空证据的新局。上述中途操作与刷新后清空均已在5b5676d版本验证。若浏览器拒绝删除记录，页面会明确告知旧记录可能残留；应先按提示清除此站点数据，再交给下一位，不能仅因界面回开场就认定记录已删除。

## 异常定位

- 服务启动失败：查看 logs/production-error.log；端口占用时选其他PORT，不能盲目终止其他程序。
- 页面卡开场：检查浏览器网络和本模式日志。已观察到的 `net::ERR_NO_BUFFER_SPACE` 是环境连接资源错误；不能据此宣布经济规则有误，也不能用静态效果图冒充游戏。
- 模型缺失：保留开发预览提示，记录缺少的模型；不要把缺失文件的占位几何算作正式资产完成。
- 数据无法保存：按页面提示继续内存局，刷新可能丢进度；不要上传云端补救。
- 再次运行前：源码变化后重新构建生产模式，避免验收的是旧构建。开发热更新不会自动替换生产构建。

## 停止

```sh
PANDA_MODE=production bash scripts/stop.sh
```

脚本只读取当前模式的进程记录，并核验命令属于本项目。日志留在项目 logs 中。正式发布、部署和独立验收均另行进行。
