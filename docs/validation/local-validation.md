# 本地玩法与运行验证

本记录是当前实现过程中的确定性测试和浏览器自查，不是用户另开的独立验收。正式视觉模型未完成时，仅验证流程，不宣布最终画面或性能达标。

## 执行方式

先通过项目脚本启动3017端口，再执行：

```sh
PORT=3017 bash scripts/start.sh
npm test
npm run test:paths
npm run test:browser
```

浏览器测试使用官方 Playwright 1.64.1 和系统 Edge 的隔离无账号上下文，不访问个人浏览器资料。报告在 logs/playwright-results.json，失败截图和追踪在 logs/playwright-artifacts。默认逐个执行，避免并发场景拖累结果。服务须保持同一轮代码稳定，其他任务热更新发生时应单独复查失败。

## 可复现输入与独立预期

- 四工四观察：骰序列3、1、1、1、1、1、1、1；四次零收支后四次工作，1000＋1200＋1000＝3200，开店后200。
- 经营：骰序列3、1、1、1、1、1、2、1，第五天桥上走音乐角支路；第一和第五天工作，第二天买摊，其余零收支，六次经营收入及终局出售后3180，开店后180。第四天已拒绝过合购，第七天对手店转入盘点，不能再次选拒绝合购。
- 未达标：使用经营路线但不购摊、不工作，2200，缺口800，仍有完整报告。
- 稳定工作：任意合法骰序列都能用工作兜底，固定落点测试为16种地点各连续八天；32个固定随机种子分别走合法骰子和分支，结算前4200，开店后1200。32种子是抽样，不是所有路线穷尽。
- 工具：第1天买摊，第2–8天分别买二手/优质工具。独立预期为1000＋1200－600－工具成本＋700＋(9－购买日)×工具加成，共14个时机用例。

浏览器测试只在点击掷骰时短暂固定随机输入，立即恢复原随机函数；正式应用没有增加测试入口、测试按钮或伪造本局记录。资料与决策通过实际可见控件操作，只读当前会话记录断言账目。

## 已完成的确定性验证

既有核心与画像20项测试通过。新增路径测试五项通过：16落点工作、32个固定种子八回合、两类工具14种购买日期、实际事件条件的3180经营路线、12事件可出现及2200未达标报告。严格类型检查通过。生产构建此前通过，后续实现修改后仍需按影响范围复查。

真实浏览器四工四观察路径已通过：43.0秒及41.4秒各完成一次完整8回合并显示3200/200。该时间属于自动操作，不支持真实观众体验时长结论。

## 首轮发现及处理

首轮报告标题断言随着报告组件改版失效，已改用稳定的清除记录入口判断报告已打开。一次合购拒绝后第七天事件已回退盘点，测试原先重复选择decline是错误输入，已修正为plan；产品未为此改动数值。

首次刷新后卡在水合开场发生在全局固定随机函数和并行热更新期间。测试现改为仅掷骰期间固定随机，修正后刷新恢复已能完成八回合；尚需最终全回归确认，不能仅据此将服务端静态资源宣布存在缺陷。直接HTTP检查五个首页脚本全部200，app-pages-internals连续三次为200。

## 真实浏览器的最终已知状态

修正后的八次工作完整用例通过：八回合4200、支付后1200，第2天选择后刷新恢复、报告证据弹窗、新局标识变化且证据清空、再完成八天、清除后刷新不恢复旧局，以及无外部请求，合计约1.1分钟。自动操作时间不能代表观众体验时长。

随后同轮3200和3180用例都在开场水合之前失败，未进行玩法操作。失败追踪的网络记录显示 main-app.js 请求响应状态为-1，`response._failureText` 为 `net::ERR_NO_BUFFER_SPACE`，约45.6毫秒内失败；同页其他Next脚本200。该错误与此前工具报告的本机套接字缓冲不足一致。开发主脚本约7.2 MB，直接HTTP可返回，但不能因此声称浏览器一定能完成加载。

证据：logs/playwright-artifacts/gameplay-四次工作四次零收支的真实路线到3200/trace.zip；当前同轮结果为1通过、2环境失败、6未执行。另行最短截图测试也未完成开场，不能将水合等待画面作为三维场景截图。没有删除.next、重置网络或调整安全设置。
