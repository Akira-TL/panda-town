# 首版任务拆分与并行安排

> 内容方向已更改：用户确认以八天量化策略展替代开咖啡馆目标。当前先审阅[新主线与文案](../design/quant-story-and-copy.md)，旧24项任务保留编号及历史证据，受影响的剧情、计算、画像和验收需同步重定义，不能按旧清单继续关票。

状态：2026-10-31 用户已授权发布并完成 24 项任务，进入资产生产与实施阶段。范围与共同规则以[首版规格](../specs/panda-town.md)为准；每份任务均可在新会话中从规格和阻塞产物接续。模型流程和授权边界见[执行提示词](execution-prompt.md)。

## 拆分原则

按玩家能看见的完整行为拆分。街区任务各自贯穿效果图、元素资产、三维地标、事件选择、状态变化和证据；画像任务各自贯穿实际记录到可展开的结论。T01 是先行视觉设计产物，T02 是最小端到端游戏；后续不是分别建立前端、后端和测试的横向队列。

每份任务含负责范围、阻塞项、局部验收和完成证据，公共经济、记录、画像和测试规则只保存在规格。优先小而完整，不为增加 Agent 数量把一个不可独立工作的功能强行切碎。

## 编号清单

1. **[T01｜生成整镇效果图与可用的基础素材包](tickets/01.md)**。阻塞：无。交付：交付能逐张查看、可供后续场景直接使用的视觉基准；覆盖双视角、对话与画像面板。

2. **[T02｜打通一次八回合的最小游戏闭环](tickets/02.md)**。阻塞：T01。交付：玩家在简化但真实的三维场景中开局、掷骰、自动移动、选择工作或观察、结算并看见本局证据。

3. **[T03｜实现弯曲街道、岔路选择和双镜头导航](tickets/03.md)**。阻塞：T02。交付：玩家在完整十六点路线中按真实骰数移动，在岔路选路并切换俯瞰观察。

4. **[T04｜面包店消费与居民回应](tickets/04.md)**。阻塞：T03。交付：玩家到面包店选择常规面包、新口味礼盒或工作，看到物件与居民回应，并留下消费情境记录。

5. **[T05｜杂货铺工具购买与经营效果](tickets/05.md)**。阻塞：T03。交付：玩家比较工具价格和未来收入影响，购买后在后续摊位收入中看到差别。

6. **[T06｜集市接手摊位、持续收入和退出](tickets/06.md)**。阻塞：T03。交付：玩家从经过集市到买下摊位、看见招牌变化、领取收入并在终局出售，完成经营路径。

7. **[T07｜研究站资料查看与来源比较](tickets/07.md)**。阻塞：T03。交付：玩家在 PandaAI 研究站查看两份明确标注的演示资料，比较来源，再完成当回合选择。

8. **[T08｜银行演示投资、行情更新与出售](tickets/08.md)**。阻塞：T07。交付：玩家读懂演示报价后投入小额资金，看到第四天与第八天变化，选择持有或出售。

9. **[T09｜礼品店选择与故事回顾](tickets/09.md)**。阻塞：T03。交付：玩家选择实用或新奇礼物，看到角色回应，并在本局回顾中找到购买依据。

10. **[T10｜户外居民互动与消息核对](tickets/10.md)**。阻塞：T03。交付：玩家在修理摊、花园、音乐角和码头完成帮忙、交谈或核对消息，选择进入本局证据。

11. **[T11｜电脑对手经营与合作采购](tickets/11.md)**。阻塞：T03。交付：玩家看见对手自己的经营进展，接受或拒绝一次采购合作后继续自己的八回合。

12. **[T12｜咖啡馆筹备、终局变现与开张](tickets/12.md)**。阻塞：T03。交付：玩家在咖啡馆查看缺口，终局确认资产变现，看到开张或筹备中，再进入画像。

13. **[T13｜消费、交易与信息习惯的证据报告](tickets/13.md)**。阻塞：T02。交付：局末展示消费取舍、交易经营和信息使用习惯，每条描述可展开到真实选择情境。

14. **[T14｜一般人格线索、兴趣与趣味称号](tickets/14.md)**。阻塞：T02。交付：局末展示有限的一般人格观察、主动兴趣和有触发依据的游戏称号。

15. **[T15｜可跳过的资料理解题与知识表现](tickets/15.md)**。阻塞：T02。交付：玩家选择回答资料中的两道客观题，看到解释，结尾只展示本局已答题表现。

16. **[T16｜组装完整画像面板与证据浏览](tickets/16.md)**。阻塞：T12、T13、T14、T15。交付：玩家从两种结局进入完整且可读的 PandaAI 用户画像面板，理解已知线索与未知部分。

17. **[T17｜本机恢复、重开与清除记录](tickets/17.md)**。阻塞：T02。交付：玩家刷新可继续当前局，重开和清除能让下一位参观者获得干净体验。

18. **[T18｜手机触控与竖屏完整流程](tickets/18.md)**。阻塞：T02。交付：手机用户能读懂对话、掷骰、选路和看报告，不需精确点击小型三维物件。

19. **[T19｜键盘操作、焦点与减少动画](tickets/19.md)**。阻塞：T02。交付：用户只用键盘也可完成核心玩法，减少动画时仍理解移动和结算结果。

20. **[T20｜完整场景的加载、性能与故障恢复](tickets/20.md)**。阻塞：T22。交付：完整小镇在目标设备可稳定运行，资源或三维能力失败时有可理解的恢复入口。

21. **[T21｜接通十六地点、十二事件与八天故事](tickets/21.md)**。阻塞：T04、T05、T06、T08、T09、T10、T11、T12、T15、T17。交付：正式小镇可从任意合法骰序列连续玩完八天，地点、事件、公告、对手和终局协调一致。

22. **[T22｜整镇双视角与画像画面的参考图对照](tickets/22.md)**。阻塞：T16、T18、T19、T21。交付：玩家看到视觉统一、布局丰富的完整小镇和画像界面，各街区拼接后仍符合选定效果图。

23. **[T23｜验证稳健与经营路径并校准事件平衡](tickets/23.md)**。阻塞：T21。交付：玩家确实能依靠稳定工作或经营达成单一目标，失败由可理解选择造成，随机路线不堵死基础机会。

24. **[T24｜展会全流程演练与可交接验收包](tickets/24.md)**。阻塞：T20、T23。交付：下一位操作者能按文档启动游戏，连续演示不同结局，清除后交给下一位参观者。

## 并行推进顺序

1. T01 完成视觉基准，再做 T02 最小闭环和公共接口。
2. T02 后，T03 导航、T13/T14/T15 三类画像内容、T17 本机存储、T18 手机、T19 键盘可以并行，共七个独立方向。
3. T03 后放开 T04/T05/T06/T07/T09/T10/T11/T12 八个内容方向；T08 需要复用 T07 的真实资料界面，因此等待 T07。同时其余画像和设备任务可以继续。
4. T16 汇总报告；T21 汇总地区、题目、生命周期和故事。两项分别负责不同公共装配，不各自改同一个总入口。
5. T22 在完整内容和双设备下做视觉对照；T23 验证经济路径，两项可以并行。T20 以完整画面测性能，T24 汇总展会演练。

这张依赖图的最大互不依赖任务集合为 14 项，表示可预留的并行任务上限，不承诺当前执行器能同时运行这么多 Agent。实际并行数受执行器能力、文件所有权和共享接口稳定程度限制。公共接口未定前不启动依赖它的任务。

## 协作边界

- T02 交付并维护公共动作、账本和扩展契约；T03 负责路线与相机；后续地区仅使用自己的地标/角色/事件内容单元。
- T13–T15 输出自己的面板区域；T16 单独装配整体报告。T21 单独装配全镇地点与故事。素材清单按所属单元维护，整合时汇总，避免所有 Agent 同时编辑一张总表。
- T18 负责响应式公共外壳，T19 负责交互语义。若实际代码出现同文件交叉，先依据所加载的协作协议明确负责范围并调整推进顺序，不能因为任务图可并行就同时改同一段代码。
- 领取、隔离工作区、任务状态、跨会话所有权和合并方式由实际加载的并行协作技能管理；本计划只声明产品依赖与责任，不创造第二套协调协议。
- 用户要求的独立验收须提供完整提示词，由用户另开会话；本任务表中的常规测试与自查不冒充该验收。

## 视觉任务的强制顺序

涉及视觉的任务必须读取[视觉生产与对照验收](../design/visual-production.md)，先调用 imagegen 生成该任务效果图，再基于效果图生成所需元素图片并作为游戏资产使用，随后制作三维形体/材质/光照/界面，最后用真实运行截图对照。已有整体概念图只提供方向，不能代替每个任务所需素材或运行画面。

T22 检查完整画面的一致性，不替前序任务兜底尚未制作的模型、图标或纹理。前序任务只有实际使用素材、完整行为与对照证据齐备后才可完成。

## 确认与发布

用户已授权执行以下拆分与验收设计：

1. 验收主要从玩家操作驱动整局，检查可见状态、独立计算的金额和可追溯画像；视觉另以双视角/双设备实际截图对照效果图。
2. 上述 24 项的粒度与阻塞是否合适，是否有需要合并或继续拆分的项目。

确认后先发布一份不带 `ready-for-agent` 的 GitHub 规格 Issue，再按依赖顺序发布 24 个任务，填写稳定来源链接、原生子任务关系及原生阻塞关系，使用仓库已配置的角色标签。发布前核对同目的现有问题，防止重复创建；不修改或关闭旧的父决策总览。

用户已明确授权实施。发布进度按实际成功的 Issue 回填，不把未成功发布或未通过验收的项目标为完成。用户不在时，重要设计问题交由 gpt-6-astra 子 Agent 提建议；不绕过验证码、付费或系统权限边界。
