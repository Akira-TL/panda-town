## 实施顺序与完成边界

1. 先确认一局一次1000、掷骰岔路到达、当前店买入/等待与背包跨店卖、下一站继续、设置随时结算可操作。
   完成标准是同一真实账户连续经历不同商品，超过八轮仍可继续，设置暂停和历史末尾不死锁。
2. 接入真实OHLCV、K线点按四价、成本线/成交点/量柱及实际现金持仓预览，
   用一次成交到下一期估值变化验证学习反馈，不能只替换文字。
3. 接入明确规则表单、六指标研究及两类客观互动。走通MACD查看→已发生交叉→解释→采用→新情境判断。
   交付时同时保留未预热、手动规则、跳过和首次错误，不把资料浏览计成掌握。
4. 接入同条件固定商人、已观察账户回撤和精简结果；按真实规则/交易/知识生成研究问题，
   主动复制并普通打开PandaAI。零交易与未作答可正常结束，不捏造操作或能力。
5. 逐图/逐点核对十张参考、15居民、16地点旋转取景以及电脑/手机/键盘/故障，
   新界面实际截图和未解决差异齐备后再进入T24真实演练。

每阶段按票中具体AC交付。数字检查可证明相应计算，不自动证明按钮、焦点、视觉或体验。
只有实际通过的限定项可勾选；父#10及24子票当前保持OPEN，完成逐项复核后由协调者更新状态。

## 确定性检查与真实操作

先用独立CSV字面量与手算检查四价、指标、成交、成本、费用、盈亏、回撤和同机会对照。
现有市场7项、指标10项及学习领域12项是局部作者证据，需按当前修改范围运行适用检查，不能混算不同版本通过数。
再在同一构建操作至少两条不同商品/持仓路线，覆盖超过八轮、跨店卖、两种互动、指标链、刷新和任意阶段设置结算。

验证交易/学习双键新局隔离、存储读写删除拒绝、原生模态焦点、纯键盘与减少动画、360/390竖屏、
模型/纹理/WebGL故障、剪贴板成功和拒绝。性能记录具体版本、实际传输、渲染器和可见采样范围，
不把软件浏览器视口当实体手机，也不把rAF回调率或报告页当GPU帧率。
5–8分钟体验由人类试玩计时，脚本耗时不能替代。

当前新学习UI的实际浏览器及视觉验收尚未完成。旧开店、旧八章和旧UI记录不作为本轮通过；
素材、类型检查、模型loaded或文档同步均不能代替未验条件。
