# Panda Town 首版产品规格

状态：2026-10-31 用户已授权完成前述任务，进入实施。当前数值仍须实测，不标为已验证的平衡结果；GitHub 规格及任务索引见任务目录。资产流程采用 imagegen → 已授权 Edge 内 Tripo → 必要时 Blender 修整 → 游戏实际使用与对照验收。

## 1. 问题

展会参观者需要在不了解金融术语的情况下，进入一座有吸引力的三维小镇，完成有后果的消费、经营与投资选择，并看懂这些选择反映了什么。PandaAI 的展示价值是把选择及其情境转成有证据的用户画像，而非仅在游戏中放一个品牌标识。

## 2. 方案

玩家扮演熊猫，在童话小镇度过八天，唯一目标是筹齐 3000 金币开咖啡馆。通过六面骰沿弯曲街道自动行走，岔路自行选择，在沿街店铺和居民处完成对话选项。现金、经营资产和演示投资随选择变化；一名电脑对手提供轻度竞争与合作。第八天结算后，进入用户画像面板，本局到此结束。

电脑展示优先，兼容手机。目标体验 5–8 分钟，阅读和选择不倒计时。首版使用演示数据，无账号、无真实交易、无用户数据上传。

## 3. 用户故事

1. 参观者能够从开场一句话看懂唯一目标、八回合期限和基本操作，直接开始。
2. 玩家能够在第三人称跟随和全局俯瞰之间切换，看见同一座有高低、弯道和地标的小镇。
3. 玩家掷骰后自动行走；岔路显示去向及沿途地点，选路后消耗剩余步数。
4. 玩家通过店铺和角色对话选择工作、消费、经营或投资，确认前能看见已知成本和不确定结果的范围。
5. 玩家查看演示资料、比较信息或回答一道理解题时，能得到与随后选择相关的内容。
6. 玩家看见自己买下的摊位、获得的物件和咖啡馆状态发生变化，选择有场景反馈。
7. 玩家看见对手经营、提出交易或合作；对手成功不剥夺自己的完整八回合。
8. 玩家能靠稳定工作达成目标，也能承担有限投资风险；不会被借款或负余额淘汰。
9. 玩家在结算时自主选择是否变现，明确看到现金、保留资产、目标缺口和最终结果。
10. 玩家在面板查看本局偏好、一般人格线索和逐条证据，能区分未观察、受限制与主动选择。
11. 玩家能够重开、刷新恢复当前局或清除本设备记录，现场换人不继承前一位玩家的画像。
12. 手机、键盘用户能完成相同核心流程，减少动画后仍看得懂掷骰、移动和结果。

## 4. 实现决策

### 4.1 场景与视觉

美术采用已选童话小镇：暖色日光、柔和阴影、圆润熊猫、木构灰泥、错落屋顶、弯曲街道、溪流和桥梁。16 个停靠点为 12 个主路点与 4 个支路点，建筑门口或户外物件承载事件；不铺棋盘格。

所有视觉任务必须执行配套的《视觉生产与对照验收》：先通过 imagegen 生成对应效果图，再参考效果图生成实际使用的元素图，最后制作真实三维模型、材质、光照和界面并进行运行截图对照。图片可用于纹理、招牌、对话头像和界面图标；需要绕行、遮挡或旋转观察的建筑与角色必须有三维形体。不能以整张概念图代替场景。

第三人称为默认镜头，全局视角允许旋转缩放；对话使用侧前方构图。切镜头不推进回合、不丢剩余步数、不重复触发事件。手机弹窗与镜头共同保证当前角色或地标仍可辨认。

### 4.2 路线和回合

主路按固定方向循环；两条支路分别从主路分出，经两个支路点后汇合。每走一条边消耗一步，无论其视觉长度。骰子公开产生 1–6，普通游戏中不改点；验收可以注入固定骰序列，与正式模式明确区分。

回合顺序：当天信息 → 掷骰 → 移动及岔路选择 → 一个主要事件 → 结果反馈 → 对手行动 → 收入结算。路过不触发主要事件。第 1、4、8 回合的引导、公告、收尾不依赖落点，也不增加主要决策次数。镜头、资料展开、全局观察均不消耗行动。

每个普通落点均提供“做一份临时工作，收入 250”作为三个选项之一，替代当回合的其他决策；不是选完后额外领取。一次性事件完成后显示后续事件，兜底工作仍可选。临时工作地点由居民转介解释，玩家不需再次掷骰去找工作。这样任何骰序列都能在八回合中选择至少四次额外工作。

按钮提交后立即锁定本次决策；快速连点、返回弹窗、刷新恢复都不能重复领收入。没有超时自动替玩家选择。第八回合仍含一个主要事件，随后进入一次终局结算。

### 4.3 经济规则

| 项目 | 首版设计值及生效时机 |
| --- | --- |
| 初始现金 / 开店门槛 | 1000 / 3000 金币 |
| 基础收入 | 每回合末 150，共八次，所有路线相同 |
| 额外工作 | 主要事件选择后即时 +250 |
| 摊位 | 支出 600；购买后的下一回合开始，每回合末 +100；最多一个 |
| 摊位退出 | 第八回合按事先说明的 480 出售，也可保留 |
| 二手 / 优质工具 | 分别 100 / 180；持有摊位时，之后每次收入额外 +20 / +40；只能拥有一种，不能叠加升级刷收益 |
| 消费纪念物 | 60 或 120；记录获得与后续角色反应，无变现价值，不新增独立资源条 |
| 演示投资 | 只在第 1–7 回合购买，投入 200 或 400；最多一笔持仓，不借贷，亏损最多为投入额 |
| 投资报价 | 每份初始 100，第 4 回合公告为 80 或 120，第 8 回合另一报价为 90 或 110；购入份数=投入/当时报价 |
| 投资出售 | 可在相关事件或终局按当前报价出售全部份额，现金四舍五入到整数；费用为 0，明确显示 |

投资情境在开局固定为甲（100→80→110）或乙（100→120→90），与骰子使用独立随机输入。只向玩家展示截至当天的数据；两个情境的抽样概率均为 1/2，是演示机制而非预测。第四回合开头更新第一次报价，第八回合开头更新第二次报价。初期不引入任意实时行情或可被语言模型改变的盈亏。

账本中现金只能由公开的收入、消费、购买、出售改变。消费前核验余额；不可买选项显示差额，不计为主动放弃。资产标明数量、成本、当前退出价值与是否可出售；纪念物归选择回顾，不计入金融资产总值。

终局先发第八回合基础收入及到期经营收入，再显示逐项出售报价和保留资产的后果，玩家确认后以现金判定是否达标。达标展示开张并记录支付开店成本后的余额；结果同时保留“结算前可用现金”，防止支付 3000 后被误判失败。未达标展示筹备中和差额，不暗中补钱。

### 4.4 剧情和电脑对手

补充确定性规则：工具区分未持有、待交货、已持有。接受合购即时扣 100，次日开头交付；待交货时禁止再次普通采购或合购。合购限第 2–7 天，第二天公告不消耗主要行动；第八天替换盘点。普通购入工具当日即生效，但仅对已开始经营的摊位当晚收入加成；新买摊位当日仍无收入。工具不可独立出售，摊位出售后无经营加成。

终局确认前可调整出售清单，确认后原子完成出售、判定、支付及结果跳转。结算前可用现金指第八天收入和本次变现之后、支付开店成本之前的现金，重复确认或刷新不得重做。

地点事件按固定优先级选择第一个符合条件的项目，落点时冻结事件及选项：广场/咖啡馆 E12；面包 E01；杂货 E02；集市 E03；公告 E06→E04；研究站首次 E04，后续 E05；银行 E06→E05；桥 E08；礼品 E07；对手店 E08；河岸 E06→E11；修理 E09；花园/音乐 E10；码头 E11。前提不符或一次性内容结束时落到 E12 转述及工作。资料与镜头操作不重选事件。

T02 必须实现并验证全部经济效果及阶段契约，包括待交货、工具、摊位、份额、报价、出售、一次性决策、存储版本、资料题目插槽；后续内容只声明效果，不重复实现账本。四次工作加四次零收支的 3200 验收使用明确可达的固定骰序列；任意骰序列保障的是八次工作可达 4200，不能把任意落点都可观察当作已有功能。

首版十二个基础事件、16 处承载地点、八天节奏与数值后果见配套《事件与场景目录》。玩家每局八个主要事件，不保证随机体验所有事件。未观察到的主题在面板如实留空；全局地图可以预览主题，不能据随机落点判断兴趣。

电脑对手按固定可解释规则推进，每回合一次简短摘要，无需再播放完整掷骰。其收入和资产使用独立账本；仅竞争明确标注的一次优惠。玩家拒绝合作仍有普通价或工作路径，不占用基础收入、咖啡馆或结算服务。电脑对手不访问玩家的隐藏画像来操控机会。

### 4.5 行为记录与画像

每条动作记录包含：本局标识、规则版本、回合、事件及独立情境标识、动作类型、当时现金与资产、实际展示的选项及可用性、已知成本与资料、用户动作、公开结果。资料显示、资料比较、作答、决策提交分开记；只看到弹窗不等于阅读或认同。

画像只使用实际可见且可选择的机会。单事件的反复展开或变体复刷不增加独立证据数；随机经过、余额禁用、未展示选项不作拒绝证据。每条描述链接原事件和情境，不以财富或结果成败推断能力。矛盾行为并列展示并注明时间、余额和目标压力。

| 面板区块 | 首版输出规则 |
| --- | --- |
| 消费取舍 | 展示价格、品质、新奇与保留现金的实际选择及可选机会数；至少两个独立情境方向一致才概括为“本局多次……” |
| 交易经营 | 展示确定收入/不确定收益选择，投入占当时现金比例，以及持有/退出；没有机会则未观察 |
| 信息习惯 | 展示主动查看、比较两份不同来源、消息变化后的调整；不由停留时间或速度推断能力 |
| 兴趣 | 至少两次不同情境的主动主题选择才概括重复兴趣，单次只列行为 |
| 知识表现 | 只有客观题才显示正确数/已作答数、原题、解释；无题或跳过显示未评估，不换算综合金融能力 |
| 一般人格线索 | 参考大五人格研究框架，展示与探索、计划、社交、合作相关的情境行为；两次不同情境且无反证才给有限文字线索；不足时显示线索不足 |

一般人格首版不计算五维分数，不把投资风险自动映射为开放性，也不把合作自动映射为宜人性。情绪稳定性缺少合适观察情境，直接说明本局未评估；其余维度如无适当证据也如此。此处的“两次”是透明的产品显示门槛，不是经心理测量验证的阈值。不复制受许可限制的量表题项，不声称八次选择完成标准人格测验。

趣味称号从可解释规则产生：“细心看账的店长”（两个独立情境主动比较资料）、“踏实筹备的店长”（至少四次临时工作），其余“初来小镇的店长”；前者优先。它们是游戏文案，不构成新的心理分类。各称号旁说明触发依据。

结尾面板先呈现开店结果，再显示上述区块、证据与未观察部分。仅提供展开证据、重开、清除；没有推荐、课程、额外练习、注册或外部跳转。PandaAI 关联通过研究站的资料决策过程与最终可解释画像体现，不声称品牌方已确认这些字段。

### 4.6 运行边界与并行接口

沿用项目已定的 Next.js 15.4、React 19、TypeScript、ESM、Tailwind CSS 4；具体三维库及版本由最小闭环任务核验兼容性后记录，当前不安装依赖。

公共行为入口接收开局、掷骰、选路、资料展开、选择、出售、镜头切换、重开和清除等明确类型动作，返回新的可见状态、场景变化与行为证据。所有经济规则与阶段推进只有一个负责模块；三维场景和对话不能各算一遍收益。

场景内容以稳定的地点和事件标识接入。各内容单元提供自己的地标、角色、对话、条件、效果声明和验收场景；只能请求已定义的经济效果。画像单元接收只读的本局证据，返回各自区域及其证据引用。地区和面板的公共装配分别由单一任务负责，后续任务提交自己的内容单元，避免共同改一个总入口。

最小闭环交付时固定公共动作、资产、事件、场景插槽、画像插槽和记录版本约定，并提供使用样例。后续 Agent 需要扩大接口时先提出明确变更及受影响任务，不在自己的支线复制核心规则。所有尚未生成的文件路径由实现时按仓库实际情况确定。

本局状态使用浏览器会话存储（sessionStorage），同一标签页刷新可恢复，关闭标签页后不保留历史；浏览器会话恢复可能恢复存储，因此展会换人必须显式重开或清除。只保存当前局，不建用户历史库。重开生成新局并清除旧证据；清除同时删除存储、内存账本及派生画像。存储不可用时改为内存运行并说明刷新将丢失。

首版所有模型、图片、字体和演示数据随项目本地提供，无第三方追踪脚本，无外部模型请求，无行为上传；不需要 Panda Data 凭据。存储版本不兼容时提示重新开始，不能混用旧规则产生新画像。

### 4.7 设备与异常

设计基准为桌面 1440×900 和手机 390×844，另检查 360 像素宽布局。主要按钮触控区域目标至少 44×44 CSS 像素。键盘可聚焦全部决策，弹窗有明确焦点与关闭/确认语义，关键状态不能仅靠颜色。

普通操作不要求精确点三维小物件；等价按钮承载掷骰、选路与事件选择。支持减少动态效果，保留结果提示。资源加载失败提供重试；三维能力不可用时明确说明，不能拿静态图标称完整游戏。低性能先降阴影、像素密度和远景装饰，保留决策与画像。

## 5. 测试决策（待本次统一确认）

当前没有应用与既有测试。首选一个最高层业务接缝：通过玩家可执行动作驱动一局，断言可见状态、账本和面板证据；实现可采用浏览器操作或与其相同的公共动作入口，预期金额来自独立手算，不复制被测算法。固定骰子、情境与选择，使失败能复现。

必备外部行为例子：

1. 四次额外工作、四次零收支观察、无资产：1000＋8×150＋4×250＝3200，开张后余额 200；任何骰序列仍能选到工作。
2. 第二回合买摊位，无工具，做两次工作，其余不花钱，终局出售：1000＋1200－600＋600＋480＋500＝3180，开张后余额 180；购买当回合无摊位收入。
3. 第一回合按 100 投入 200，情境甲，第八回合卖出获得 220；情境乙获得 180。已知报价更新前不能提前显示未来价格。
4. 余额不足、重复提交、重复结算、刷新恢复和不兼容存储均不制造现金或额外证据。
5. 同一事件反复查看只是一项独立情境；没有知识题、没有可用消费选项、矛盾行为、未出现人格情境均输出对应缺失状态。
6. 达标与未达标都能进入报告，重开与清除后看不到前一位玩家的证据；浏览器网络检查无原始行为或画像上传。

视觉以真实运行截图对照 imagegen 参考：同一地标的第三人称和俯瞰、街道转弯、两种结局、手机弹窗。记录镜头和场景条件、差异及修复结果。视觉图不替代功能验收，功能通过也不代表画面达标。

性能为待实测预算：目标桌面 60 帧/秒、移动端 30 帧/秒；正式验收记录具体设备、浏览器、分辨率和至少 60 秒运行期间的中位数与第 95 百分位帧耗时。首屏压缩传输目标不超过 15 MB，首局总加载目标不超过 40 MB；超出须说明实测影响及优化结果。未指定实体设备前不声称完成性能达标。

每个任务只验证自己新增的完整行为与必要回归。最后汇总两条差异路线、八回合全流程、资源失败和展会换人。当前 Agent 自查与确定性验证不冒称独立 Agent 验收；如需要独立验收，提供提示词交由用户另开会话执行。
